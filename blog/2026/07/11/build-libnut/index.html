构建 Libnut：麒麟与 Win7 编译备忘

July 11, 2026 · 4 min read

纯编译备忘：在银河麒麟与 Win7 上自行构建 libnut.node，绕过官方预编译包不兼容的问题。源码用 libnut-core v2.7.5。

麒麟​

在 麒麟机器上，基于 2.7.5 分支进行编译，产物 build/Release/libnut.node 可以正常的运行在 麒麟 CPU 中。

Windows​

由于有些设备是 windows 7 ，npm 上的产物 无论是 https://www.npmjs.com/package/@computer-use/libnut-linux 还是 https://www.npmjs.com/package/@nut-tree-fork/libnut-linux 都无法正常运行。

因此，在一台 windows 11 的机器上，使用 cmake  + Visual Studio 2015 编译。

 Visual Studio 2015 只有 ISO 镜像，下载社区版后通过 WinCDEmu 装载才能安装。安装依赖

  • Programming Languages → Visual C++ → 常见工具
  • Windows 8.1 SDK 和 运行时
  • Visual C++ 2015 生成工具

如果 CMake 找不到，试试 https://github.com/Kitware/CMake/releases/tag/v3.23.2 。

VS2015 编译器默认使用 Unicode 字符集，但 libnut 代码用的是多字节 (ANSI)，不兼容！

在 VS2015 Developer Command Prompt 里，先执行这一句，再编译：

set CFLAGS=/D_UNICODE /DUNICODE
set CXXFLAGS=/D_UNICODE /DUNICODE

然后再跑编译命令：

cmake-js rebuild --CDCMAKE_OSX_ARCHITECTURES="x86_64"

其中源码 screengrab.c 有一些 win 10 的API， 让 AI 改写以适配 Win 7 。

问题排查与修复过程汇总​

背景​

  1. 运行环境：Windows 7、Node.js 20
  2. 项目依赖：@computer-use/libnut-win32 / libnut-core 2.7.5
  3. 核心故障：启动项目加载原生模块 libnut.node 失败，报错 The specified procedure could not be found，属于高版本二进制模块与 Win7 不兼容问题。

阶段1：基础环境兼容问题​

  1. Node.js 20 官方不支持 Win7，原生 .node 二进制文件加载直接报错。
  2. 解决方案：使用 NVM 切换固定为 Node 16.20.2（Win7 最后稳定兼容版本）。
  3. 衍生问题：nvm use 在 VS2015 开发者命令行临时生效、重启失效，为后续编译埋下环境隐患。

阶段2：Windows 编译依赖缺失​

  1. 安装依赖时触发 windows-build-tools 报错，原因为新版 Node 与废弃工具包语法不兼容。
  2. 手动搭建 C++ 编译环境：
    • 安装 Visual Studio 2015
    • 安装 CMake 3.23.6（Win7 最后支持版）
    • 补充安装 Windows 8.1 SDK，解决系统 SDK 缺失报错

阶段3：C++ 编译报错连续修复​

  1. 缺少 C/C++ 编译器：补全 VS2015 C++ 开发组件，修复 CMAKE_C_COMPILER 未找到错误。
  2. 字符集冲突报错：GetWindowTextW 宽字符/窄字符不匹配，修改源码调用 ANSI 接口 GetWindowTextA 解决编译阻断。
  3. Win10 专属 API 报错：
    • 源码内置 DPI_AWARENESS_CONTEXT、SetThreadDpiAwarenessContext、IsWindows10OrGreater 等 Win10 专属函数
    • Win7 无对应系统 API，直接删除/注释高版本系统专属逻辑，保留原生截图、键鼠核心能力
  4. 头文件路径、类型转换警告：修复头文件引用、兼容 VS2015 老旧编译器语法。

阶段4：最终改造方案​

  1. 基于官方原版 screengrab.c 源码，移除全部 Win10 DPI 适配代码。
  2. 保留原有截图、位图处理、窗口矩形计算核心逻辑，纯适配 Win7 系统。
  3. 清理编译缓存，通过 cmake-js rebuild 完成全量编译，生成 Win7 可正常加载的 libnut.node 原生模块。

核心结论​

  1. 根本矛盾：新版 libnut 预编译包基于 Win10+ 编译，无法在 Win7 运行。
  2. 最终方案：放弃预编译二进制包，在 Win7 + VS2015 + Node16 环境下本地改造源码、自行编译。
  3. 环境标准组合（Win7 稳定可用）：Win7 + Node 16.20.2 + VS2015 + Windows 8.1 SDK + CMake 3.23.6。

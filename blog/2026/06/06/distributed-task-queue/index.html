分布式任务队列与调度器：Celery、BullMQ、Agenda

June 6, 2026 · 2 min read

有了 MQ 为什么还要 Celery / BullMQ？类比 WebSocket 和 Socket.IO：底下是管子，上面是带重试、房间、编排的水龙头。

MQ vs 任务框架​

层级通信任务
底层传输WebSocketRabbitMQ / Redis Stream 等
上层框架Socket.IOCelery / BullMQ / Agenda

框架补的是：任务签名、重试退避、结果查询、Group/Chain/Chord、定时、路由、监控（如 Flower）。

Celery（Python）​

在 MQ 之上做一站式任务生产 / 调度 / 执行 / 监控。add.delay(4, 4) 这种调用体验，靠的是序列化函数名和参数，而不是手写裸消息。

Redis 原料 vs BullMQ（Node）​

Redis 自带 List / PubSub / Stream，但可靠任务系统通常还要状态机、延迟队列、优先级、并发限制。BullMQ 用多套 Redis 结构 + Lua 保证原子性，提供至少一次语义、Cron、进度、多 Worker 分片。

Agenda（偏定时调度）​

传统后端是 MongoDB + 轮询拉取 + 分布式锁；6.x 起可插拔存储（含 PG / Redis），并可用 Pub/Sub 或 LISTEN/NOTIFY 做实时触发。

怎么选​

BullMQAgenda
存储RedisMongo / PG / Redis（6.x）
哲学高性能队列持久化定时调度、API 简洁
触发偏推送传统轮询，6.x 可加实时通道
适合高并发复杂任务与 Mongo/PG 栈契合的 cron 场景

一句话：MQ / WebSocket 解决通信；Celery / BullMQ / Agenda / Socket.IO 解决业务侧的可靠性与编排。选型看技术栈和「队列吞吐 vs 可靠定时」谁更重要。

ClawShell API 密钥保护机制分析

June 27, 2026 · 7 min read

关于 clawshell 如何保护 API 密钥的研究笔记。面向 Agent 与上游 LLM 之间的本地反向代理。

关于 clawshell 如何保护 API 密钥的研究笔记

概述​

ClawShell 是一个安全优先的反向代理，专为 OpenClaw/Hermes Agent 生态系统设计。它位于 Agent 与上游 LLM 提供商（OpenAI、Anthropic、OpenRouter）之间，提供以下功能：

  • 虚拟密钥到真实密钥的映射
  • DLP（数据丢失防护）扫描请求和响应体

安全模型：无沙箱 — 使用 Unix 权限分离​

ClawShell 不使用操作系统级沙箱（容器、VM、seccomp）。相反，它依赖于：

  1. Unix 权限分离（setuid/setgid）
  2. 文件系统权限（/etc/clawshell 目录权限 700）
  3. systemd 沙箱加固（Linux）

密钥保护机制​

层级机制
1. 密钥隔离真实 API 密钥存储在 /etc/clawshell/clawshell.toml（权限 700），由 clawshell 系统用户拥有
2. 权限降级进程启动后从 root 降级到 clawshell 用户（通过 setuid()/setgid()）
3. 虚拟密钥映射OpenClermes Agent 只能看到虚拟密钥（如 vk-alice-001），永远看不到真实密钥
4. DLP 扫描使用正则表达式扫描请求/响应体中的 PII（个人敏感信息）
5. 仅限本地环回管理统计端点限制为仅 127.0.0.1 可访问

"clawshell" 系统用户​

clawshell 系统用户在 sudo clawshell onboard 期间创建，作为安全锚点。

创建过程（按平台）​

Linux（src/platform/linux.rs）：

useradd --system --no-create-home --shell /usr/sbin/nologin clawshell

macOS（src/platform/macos.rs）：

dscl . -create /Users/clawshell
dscl . -create /Users/clawshell UniqueID 400-500
dscl . -create /Users/clawshell UserShell /usr/bin/false
dscl . -create /Users/clawshell IsHidden 1

核心代码实现​

1. 虚拟密钥提取（src/keys.rs）​

pub fn extract_virtual_key(auth_header: &str) -> Option<&str> {
    let trimmed = auth_header.trim();
    if let Some(key) = trimmed.strip_prefix("Bearer ") {
        let key = key.trim();
        if key.is_empty() {
            None
        } else {
            Some(key)
        }
    } else {
        None
    }
}

2. 密钥解析（src/keys.rs）​

pub fn resolve(&self, virtual_key: &str) -> Option<&ResolvedKey> {
    self.mappings.get(virtual_key)
}

3. 权限降级（src/process.rs）​

pub fn drop_privileges() -> Result<(), Box<dyn std::error::Error>> {
    if !getuid().is_root() {
        return Ok(());
    }

    let user = User::from_name("clawshell")?
        .ok_or("system user 'clawshell' not found")?;

    setgid(Gid::from_raw(user.gid.as_raw()))?;
    setuid(Uid::from_raw(user.uid.as_raw()))?;

    info!("Dropped privileges to 'clawshell'");
    Ok(())
}

4. 真实密钥注入（src/proxy.rs）​

match provider {
    Provider::Openai | Provider::Openrouter => {
        req_headers.insert(
            AUTHORIZATION,
            HeaderValue::from_str(&format!("Bearer {}", real_key))?,
        );
    }
    Provider::Anthropic => {
        req_headers.insert(
            "x-api-key",
            HeaderValue::from_str(real_key)?,
        );
        req_headers.insert(
            "anthropic-version",
            HeaderValue::from_str(&self.anthropic_version)?,
        );
    }
}

systemd 沙箱加固（Linux）​

生成的 systemd 单元包含大量加固措施（src/platform/linux.rs）：

[Service]
Type=exec
User=clawshell
Group=clawshell
NoNewPrivileges=true
PrivateTmp=true
PrivateDevices=true
ProtectSystem=strict
ProtectHome=true
ProtectControlGroups=true
ProtectKernelModules=true
ProtectKernelTunables=true
ProtectKernelLogs=true
ProtectClock=true
ProtectHostname=true
ProtectProc=invisible
ProcSubset=pid
LockPersonality=true
RestrictSUIDSGID=true
RestrictRealtime=true
MemoryDenyWriteExecute=true
CapabilityBoundingSet=
AmbientCapabilities=
RestrictAddressFamilies=AF_INET AF_INET6
UMask=0077
ReadOnlyPaths=/etc/clawshell

这可以防止 clawshell 进程：

  • 提权
  • 写入任意路径
  • 访问内核接口
  • 发起原始网络调用（仅允许 TCP）

重要限制：Root 可以读取配置​

是的，root 可以读取 /etc/clawshell/clawshell.toml — 这是 Unix 的基本特性。Root（UID 0）可以绕过所有文件权限检查。

这意味着什么​

场景受保护？
主机上的 root 用户❌ 否（设计如此）
被攻陷的 Agent✅ 是 - 使用虚拟密钥
沙箱逃逸✅ 是 - 沙箱限制损害范围
外部攻击者（通过网络）✅ 是 - 仅限环回
日志中的意外 PII✅ 是 - DLP 会脱敏

设计假设​

保护机制假设 root 是可信的（系统管理员），但 Agent 是不可信的（可能执行任意用户代码）。这是一个合理的威胁模型 — root 需要管理系统，而 Agent 不应该访问真实凭证。

安全层级总结​

┌─────────────────────────────────────────────────────────────┐
│                    安全层级                                  │
├─────────────────────────────────────────────────────────────┤
│  层级 1: 虚拟密钥      → Agent 永远看不到真实密钥           │
│  层级 2: 文件权限      → 普通用户被阻止                      │
│  层级 3: systemd 沙箱  → 进程无法逃逸                        │
│  层级 4: DLP 扫描      → PII 在记录前被脱敏                  │
└─────────────────────────────────────────────────────────────┘
                         ↑
                    Root 可以读取
                    （但负责管理系统）

OpenClaw/Hermes Agent 如何连接 ClawShell​

在 sudo clawshell onboard 期间，ClawShell 会配置下游 Agent（OpenClaw 或 Hermes Agent），使其通过本地代理路由所有 LLM 请求，并使用虚拟密钥。

架构：Agent → ClawShell → 上游提供商​

┌─────────────────┐     虚拟密钥           ┌──────────────┐    真实密钥     ┌─────────────────┐
│  OpenClaw 或    │ ──────────────────►   │  ClawShell   │ ──────────────►  │  OpenAI /       │
│  Hermes Agent   │   "Bearer vk-..."     │  代理        │   "Bearer sk-.." │  Anthropic      │
│                 │   (虚拟密钥)          │  :18790      │   (真实密钥)     │  API            │
└─────────────────┘                       └──────────────┘                  └─────────────────┘

OpenClaw 集成​

ClawShell 在 onboarding 期间修改 ~/.openclaw/openclaw.json：

配置变更（src/onboard/openclaw_json.rs）：

{
  "env": {
    "CLAWSHELL_API_KEY": "vk-alice-001"    // ← 虚拟密钥
  },
  "agents": {
    "defaults": {
      "models": {
        "clawshell/gpt-5.2": {             // ← 自定义模型条目
          "id": "gpt-5.2",
          "name": "gpt-5.2"
        }
      }
    }
  },
  "models": {
    "providers": {
      "clawshell": {                       // ← 自定义提供商
        "baseUrl": "http://127.0.0.1:18790/v1",
        "api": "openai-completions",
        "apiKey": "${CLAWSHELL_API_KEY}"   // ← 引用环境变量
      }
    }
  }
}

工作流程：

  1. OpenClaw 发送请求到 http://127.0.0.1:18790/v1/chat/completions
  2. 使用 ${CLAWSHELL_API_KEY} 环境变量作为 Authorization header → Bearer vk-alice-001
  3. ClawShell 接收虚拟密钥，查找真实密钥，注入后转发到上游

Hermes Agent 集成​

ClawShell 在 onboarding 期间执行 hermes config set 命令（src/onboard/hermes_config.rs）：

hermes config set model.provider clawshell
hermes config set model.base_url http://127.0.0.1:18790/v1
hermes config set model.default claude-sonnet-4-5-20250929
hermes config set model.api_key vk-alice-001   # ← 虚拟密钥

Hermes 将配置存储在 ~/.hermes/config.yaml，密钥存储在 ~/.hermes/.env。

关键洞察：虚拟密钥永不离开本地​

组件看到的内容
OpenClaw/Hermes虚拟密钥（vk-alice-001）+ 127.0.0.1:18790
ClawShell真实密钥（sk-ant-...）来自 /etc/clawshell/clawshell.toml
上游提供商真实密钥（sk-ant-...）作为正常 API 调用
日志/错误消息仅显示虚拟密钥（真实密钥永不记录）

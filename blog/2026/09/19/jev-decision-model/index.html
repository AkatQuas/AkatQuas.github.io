Jev：不生成文本的决策模型在 Agent 架构中的位置

September 19, 2026 · 7 min read

Jev 是 TypeSafe AI 的「不生成自然语言、只输出类型化决策」模型。这篇整理它在 Agent 循环里该站哪一层，以及什么场景值得上、什么场景别硬上。

一、Jev 是什么​

Jev 是 TypeSafe AI 推出的首个“System One Model”，创始人 Diogo Almeida 是 RLHF 的共同发明者之一。它的核心特征：

  • 不生成任何自然语言文本，只输出类型化决策
  • 三种输出原语：Choice（从预设选项中选一个，带概率）、Score（按标准评分）、Noul（是/否的概率判断）
  • 每个决策都附带校准过的置信度
  • 输入价格 $0.042/百万 token，输出免费；延迟 70–500ms
  • 定位是“机器原生智能”：像代码一样可靠、快速、类型安全

它不是一个更小的 LLM，而是一个专门做“窄判断”的决策引擎。

二、核心区分：决策点 vs 生成点​

这是理解 Jev 的关键框架（来自“编码器卷土重来”）：

  • LLM 的 token 生成：每生成一个 token 都要跑一次完整前向传播，输出覆盖整个词表的概率分布。本质上是“开口说话才能表达判断”——哪怕只是想知道“该左转还是右转”，也得先组织语言。
  • Jev 的判断：不走自回归解码，直接在你给定的选项空间上打分。像一个“直接举牌的人”，不发出任何声音。

Agent 循环中的大量判断（路由、验证、终止、安全门控）本就不需要生成文本。 让它们每次都以完整 prefill 的方式完成，就是“成本结构不可持续”的根源。Jev 的架构意义，就是把这些判断从 token 生成流程中彻底剥离出来。

三、Jev 在 Agent Loop 中提升的是工具链，不是推理链​

环节谁负责性质
理解意图、生成代码/文本、规划复杂任务主 LLM推理链（生成性、开放式）
选择工具、判断安全、评估完成度、路由Jev工具链（判断性、答案有限）
执行分支逻辑确定性代码零成本、可靠

Jev 从不“推导为什么”，只回答“该走哪一步”。它提升的是执行层面的决策吞吐量和可靠性，不是 agent 的思考深度。

四、Jev 不会彻底代替 LLM​

  • Jev 不生成文本，无法写代码、写文档、做开放推理
  • 它的“零幻觉”指的是输出不超出预设格式，但判断本身仍可能出错
  • 准确性高度依赖你喂给它的“现场材料”，没有内置世界知识
  • 独立基准显示：在 SMS 垃圾邮件识别（AUROC 1.00）、TREC 分类（0.93）上表现扎实；但在 Banking77（77 类意图）上低于基线，大选项集下表现下降

它的定位是“智能 if 语句”，替代的是那些“不必要地动用了写论文的大脑去回答是/否问题”的判断环节。

五、系统化的落地场景：四层架构​

第一层：Agent 控制流（最成熟）​

  • 工具调用门控：执行 shell 命令前，Jev 做 clear/caution 判断。Vercel 实践显示速度提升 5–18 倍
  • 路由与工具选择：从候选模型/工具/子 Agent 中选一个，带概率
  • 循环控制与验收：判断“是否推进了目标”、“是否真正完成”、“继续/重试/求助/停止”

第二层：上下文与输出治理​

  • 上下文压缩：fast-jev-compaction 用 Jev 评分工具输出，按相关性压缩上下文。实测 pass@1 从 22/30 提升到 25/30，最极端案例避免了 146 万字符导致的超时
  • 输出验证与护栏：检查回复是否泄露系统提示、是否包含提示注入

第三层：信息处理与提取​

  • 大规模分类与筛选：40 秒分析 724 个广告、生成 8724 个判断，成本约 9 美分
  • 信息提取与结构化：从文本中“选择”而非“生成”字段值
  • 重排序：在 RAG 流程中对文档或代码片段做相关性评分

第四层：仿真与实验环境​

  • 具身智能仿真：MuJoCo 中完成机械臂抓取（$0.0188，为 GPT-6 的 1/315）、精细操作
  • 游戏与模拟环境：Pac-Man、俄罗斯方块、驾驶模拟
  • 自动驾驶仿真：基于 Three.js 的模拟器 JevPilot中以每秒 1.5–4 次做转向决策

明确不推荐：真实自动驾驶控制回路、真实机器人硬件控制、开放式文本生成、需要世界知识的复杂推理。

六、LLM 路由分发：Jev 的天然主场​

路由决策的本质就是一个典型的 Choice 问题：答案空间有限、高频调用、需要置信度。

社区实证：

  • Jev Codex Router：per-turn 模型路由，237 轮真实对话回放中节省约 60% 成本，每次路由 $0.00003、约 0.6 秒
  • NeMo Switchyard 场景：替换 Gemini Flash 做路由分类后，延迟和成本同时改善
  • Agent Skill Router：准确率 94.4%（vs 词法基线 70.8%），72 个案例中 0 个错误路由
  • LlamaIndex 集成：JevSingleSelector / JevMultiSelector，nDCG@5 从 0.340 提升到 0.396，每次查询约 $0.0003

与 SGLang Router 的关系：SGLang Router 解决基础设施层的请求分发（cache-aware load-balancing），Jev 解决语义层的“该用哪个模型”。两者可叠加：Jev 决定用哪个模型，SGLang Router 负责高效分发。

七、在 LLM 训练中的潜在用途（后训练阶段）​

Jev 不是用来“训练”一个更聪明的 LLM，而是用来监督训练过程中的关键组件：

  • 奖励模型的替代或补充：RLHF 的奖励模型本身不校准，倾向于惩罚“我不确定”、奖励“自信地胡说”。Jev 的 RLCD 训练目标恰恰是概率校准
  • 训练数据筛选：jev-curate 用 Jev 对语料做“通过/拒绝”门控
  • 在线 RL 的奖励信号：用校准过的分数引导策略模型走向“知道自己不知道”
  • Agent 训练中的轨迹验证：快速判断操作轨迹是否安全、是否推进目标

八、本地化部署方案​

Jev 本体闭源，但社区有多个开源复刻：

方案基础模型特点
LitJevQwen 全系列最接近 Jev 接口，直接读 logits 打分，需 H100
OpenJev (DiffusionGemma)DiffusionGemma 26B-A4B开箱即用，兼容 Jev wire API
Verdict-open-jevModernBERT 151M带 RLCD 训练，概率校准，CPU 可跑
Windows 一键包Deberta-v3-large免配置，适合快速体验

关键警告：社区复刻在准确率、校准质量和语言支持上与原版有差距。概率校准——Jev 的核心技术贡献——在大多数复刻中并未被完整复现。生产使用前必须在你自己的数据上做校准验证。

九、落地优先级建议​

  1. 先做工具调用门控：收益最直接（安全 + 成本），集成路径最清晰
  2. 再做 Agent 循环控制：Token 节省和延迟降低最显著
  3. 然后做上下文压缩和输出验证：作为增量优化
  4. 最后探索信息处理场景：分类、提取、重排序，需先验证校准质量

所有落地的前提：用你自己的标注数据验证 Jev 的置信度是否校准。如果 90% 置信度的判断确实有约 90% 正确率，就可以放心设阈值自动执行；否则需要保留人工审核或 LLM 兜底。

十、一句话总结​

Jev 的架构意义，是把 Agent 循环中那些“高频、窄范围、答案可枚举”的判断，从 LLM 的 token 生成流程中剥离出来，让决策变得像调用一个带语义理解能力的 if-else 函数一样便宜和快速。它不是要取代 LLM，而是让 LLM 只在真正需要生成和开放推理的时候才被唤醒。

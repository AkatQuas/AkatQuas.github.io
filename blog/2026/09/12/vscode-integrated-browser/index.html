VS Code Integrated Browser：BrowserView、CDP 与「Add to Chat」

September 12, 2026 · 3 min read

说明：基于约 2026 年 9 月 前后对 microsoft/vscode 源码路径的阅读整理。Electron / CEF / CDP 细节会随主线漂移，落地前请对照当时仓库提交。

VS Code 桌面版的 Integrated Browser 能内嵌页面并挂 DevTools，还能把选中 DOM 丢进 Agent 对话。它并不是「绕过了 Webview」，而是根本没用扩展用的那套 Webview。

结论先行​

  • Integrated Browser = 主进程里的 Electron BrowserView / WebContents，不是扩展 WebviewPanel。
  • 内置 DevTools 靠把该 WebContents 的 Chrome DevTools Protocol（CDP） 经 IPC / ProxyChannel 暴露给 Workbench。
  • extensions/simple-browser 才是 Webview + iframe 路线，受 CSP / 资源映射限制，不能同等 attach CDP。
  • Qt + CEF 可以复刻同一套思路：remote debugging / CDP 代理 + preload + Overlay/DOM 抽节点。

实现骨架（VS Code）​

主进程封装 BrowserView（导航、权限、缩放、console），并挂 inspector / debugger 等子模块。Workbench 通过 BrowserViewGroup 一类会话分组，对目标 WebContents sendCDPMessage / 收事件。

跨 iframe：对 Target auto-attach，preload 注入 frame token，用 Runtime.evaluate 探测，把 CDP target 与 WebFrameMain 对齐，才能做元素高亮与选取。

Web 构建下这些能力会直接不可用——依赖桌面 Chromium 宿主。

和 Webview 的分界​

Integrated Browsersimple-browser / 扩展 Webview
载体BrowserView / WebContentsWebviewPanel + iframe
调试可代理完整 CDP基本是 postMessage 自有上下文
限制主进程权限与证书策略CSP、资源映射、沙箱

所以不是魔法绕过，是两条组件路径。

「选中元素 → Agent 对话」​

典型链路：

  1. 上下文菜单或 inspector 触发 add-to-chat
  2. 在正确 frame 的 executionContext 上拿到 objectId / backendNodeId（常靠 preload 的 getElement(id)）
  3. 串 DOM.describeNode / getBoxModel / getOuterHTML、Runtime.callFunctionOn、可选 Page.captureScreenshot
  4. 打包成 attachment，交给 Chat / Agent 上下文

关键仍是：正确的 frame + CDP DOM/Runtime/Overlay，而不是截一张全页图靠视觉猜。

Qt + CEF 可否同构​

可以。对应关系大致是：

  1. 开 --remote-debugging-port（或等价 CEF API），或内嵌 DevTools frontend 连 websocket
  2. 应用内做 CDP 会话管理：Runtime/Page/DOM/Overlay.enable，Target.setAutoAttach
  3. OnContextCreated 注入 helpers / element id
  4. 听 Overlay.inspectNodeRequested 或自建右键「Add to Chat」，抽节点后经 Qt 信号丢进对话模型

注意：端口只绑本机；确认 CEF 版本对 Target/Overlay 的支持；跨域 iframe 优先 backendNodeId 路径；截图与大 outerHTML 要按需、异步。

小结​

Integrated Browser 的价值是 原生 WebContents + 可代理的 CDP，从而调试和「元素进 Agent」都落在同一条调试平面上。复刻时优先对齐 CDP 与 frame 映射；Webview 路线从一开始就不在同一能力集里。
